# N-07 · assemble_asof_evidence — 판단 시점의 근거 구성

> **설계 초안 v0.1 / 미구현** · P1 · 소속 [B-02](../big-nodes/B-02.md). [Small Node 목록](README.md) · [공통 반환](common-result-contract.md)

## 1. 단일 책임과 실행 경계

실제 그 시점에 알 수 있었고 현재 조사 버전에 유효한 증거만 묶는다. 미래 자료로 과거 판단을 바꾸지 않는다.

- LLM 사용: **사용하지 않음**.
- 업무 Tool: 직접 Tool 호출 없음. as-of 조회 자체는 [TOOL-02](../tools/TOOL-02.md)에서 수행.
- 이 문서의 내부 함수는 설계 함수다. 별도 Tiny Node나 별도 LLM 호출로 세지 않는다.
- 순서·조건부 엣지는 소속 Big Node가 관리한다. 이 노드는 다음 노드를 직접 실행하지 않는다.

## 2. 입력 계약

| 입력 | 타입·제약·출처 |
|---|---|
| `EvidenceBundle, RevalidationReport` | 조회 결과와 유효성 |
| `decision_at, scenario_cutoff` | offset이 명시된 시각과 모의 정책 |
| `current_input_version` | 새 쓰기 검토에 사용할 현재 버전 |

하네스는 ID·계약 버전·권한 binding을 검사한 상태를 전달한다. 모델이 작성한 ID나 상태를 검증 없이 신뢰하지 않는다.

## 3. 내부 처리 순서

1. known_at ≤ decision_at과 revision의 유효 구간을 코드로 검사한다.
2. event_time만 보고 당시 이미 수신했다고 추측하지 않는다.
3. 도착 완료 플래그도 당시 batch_versions에서 읽는다.
4. 마감 전 판단과 이후 후속 대응을 별도 사실로 구성한다.
5. 과거 조회 근거를 현재 쓰기 승인으로 사용하지 못하게 expected_input_version을 분리한다.

## 4. 구현할 내부 함수

| 함수 개념 | 책임 |
|---|---|
| `select_known_revision(history, decision_at)` | 당시 revision 선택 |
| `validate_temporal_coverage(bundle)` | 미래·누락·혼합 snapshot 검사 |
| `build_asof_bundle(records, flags)` | 판단 시점의 구조화 근거 |

업무 실행 노드는 `node(state: ReconciliationState, services: RuntimeServices) -> NodeResult[T]`를 기본 인터페이스로 한다. 평가 노드 N-16~19는 별도 `EvaluationContext`를 입력받으며 Agent State와 공유하지 않는다.

## 5. 출력 계약

공통 `status/data/diagnostics/outcome` 외피를 유지한다. 아래는 `data`의 최소 결과다.

| 결과 | 내용 |
|---|---|
| `AsOfEvidence` | 당시 최신 revision·완결성·시점·근거 refs |
| `temporal_flags` | late_arrival/retroactive_correction/after_cutoff/unknown |

| outcome 후보 | 뜻 |
|---|---|
| `asof_ready` | 시점 일치 근거 |
| `waiting_for_input` | 당시 도착 미완료 관측 |
| `temporal_unknown` | 이력·시각 불확실 |

`status=success`는 이 함수의 검사가 정상 종료됐다는 뜻이다. 대사 일치·쓰기 성공·최종 완료·공격 방어 성공은 각 업무 결과와 실제 상태로 판정한다. partial 허용 여부는 안전한 관측 보존에 한정하며 승인·쓰기·완료 허가를 partial로 통과시키지 않는다.

## 6. 오류·재시도·예산

| 오류·조건 | 처리 |
|---|---|
| `FUTURE_INFORMATION` | 미래 행을 격리하고 잘못된 bundle 차단 |
| `INVALID_TIMESTAMP` | 시각을 임의 보정하지 않음 |
| `EVIDENCE_STALE` | 현재 쓰기 근거와 분리 |

재시도 여부는 상위 Big Node와 공통 누적 예산이 결정한다. Tool·모델 호출 전에 예산을 예약하고 실패·재개 비용도 남긴다. 저장·권한 오류를 성공으로 폴백하지 않는다.

## 7. 지속 상태·추적

event_time·known_at·decision_at·revision refs·시점별 input_version.

node_id·logical_run_id·session_id·입출력 ref·상태·에러·실행 시간을 run_events에 연결한다. 저장 형식·복구 우선순위는 [지속 상태 계약](../contracts/persistence-and-recovery.md)을 따른다.
