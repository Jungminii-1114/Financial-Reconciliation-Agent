# N-18 · generate_counterexamples — 금융 반례·정상 변환 생성

> **설계 초안 v0.1 / 미구현** · P1 · 소속 [B-06](../big-nodes/B-06.md). [Small Node 목록](README.md) · [공통 반환](common-result-contract.md)

## 1. 단일 책임과 실행 경계

검증 수준의 누락을 시험할 통제된 변환을 생성하고 독립 검사로 의도한 성질을 확인한다.

- LLM 사용: **사용하지 않음**.
- 업무 Tool: 모델 Tool 없음. 테스트 fixture 변환기.
- 이 문서의 내부 함수는 설계 함수다. 별도 Tiny Node나 별도 LLM 호출로 세지 않는다.
- 순서·조건부 엣지는 소속 Big Node가 관리한다. 이 노드는 다음 노드를 직접 실행하지 않는다.

## 2. 입력 계약

| 입력 | 타입·제약·출처 |
|---|---|
| `clean fixture, transformation_id, seed` | 정상 입력과 변환 명세 |
| `target_layer` | 입력 사건 / runtime 검증기 fixture / evaluator 자체 검사 |
| `expected property` | 유지할 조건·깨뜨릴 조건 |

하네스는 ID·계약 버전·권한 binding을 검사한 상태를 전달한다. 모델이 작성한 ID나 상태를 검증 없이 신뢰하지 않는다.

## 3. 내부 처리 순서

1. 서로 다른 두 금액을 교환하여 합계·건수는 보존하고 거래별 대응만 깨뜨린다.
2. 한쪽 거래 연결 변경, 다른 batch 성공 근거, 과거 입력 승인 참조를 각각 분리한다.
3. 정상 대조로 양쪽 transaction IDs를 일관되게 치환하고 관련 refs도 같이 갱신한다.
4. 불변·변경 성질을 생성기와 다른 검사로 확인한다.
5. 제약이 맞지 않는 변환은 사례로 채택하지 않으며 실제 서버 보호를 제거해 성공시키지 않는다.

## 4. 구현할 내부 함수

| 함수 개념 | 책임 |
|---|---|
| `apply_transformation(fixture, kind)` | 지정 필드만 변경 |
| `validate_transformation(original, changed)` | 보존·위반 조건 검사 |
| `emit_case_manifest(artifact)` | 원본·변환·정답 refs 기록 |

업무 실행 노드는 `node(state: ReconciliationState, services: RuntimeServices) -> NodeResult[T]`를 기본 인터페이스로 한다. 평가 노드 N-16~19는 별도 `EvaluationContext`를 입력받으며 Agent State와 공유하지 않는다.

## 5. 출력 계약

공통 `status/data/diagnostics/outcome` 외피를 유지한다. 아래는 `data`의 최소 결과다.

| 결과 | 내용 |
|---|---|
| `CounterexampleArtifact` | 원본/변환 hash·변경 위치·보존 성질·기대 실패 |
| `transformation validation` | 결정적 독립 검사 결과 |

| outcome 후보 | 뜻 |
|---|---|
| `counterexample_valid` | 의도한 실패 조건 확보 |
| `valid_control` | 일관된 정상 변환 |
| `transformation_rejected` | 변환 전제 불충족 |

`status=success`는 이 함수의 검사가 정상 종료됐다는 뜻이다. 대사 일치·쓰기 성공·최종 완료·공격 방어 성공은 각 업무 결과와 실제 상태로 판정한다. partial 허용 여부는 안전한 관측 보존에 한정하며 승인·쓰기·완료 허가를 partial로 통과시키지 않는다.

## 6. 오류·재시도·예산

| 오류·조건 | 처리 |
|---|---|
| `TRANSFORM_PRECONDITION` | 같은 두 금액 등 퇴화 사례 제외 |
| `EXPECTED_PROPERTY_FAILED` | 정답을 강제로 맞추지 않음 |
| `REFERENCE_INTEGRITY_ERROR` | 연관 ID 참조 갱신 검사 |

재시도 여부는 상위 Big Node와 공통 누적 예산이 결정한다. Tool·모델 호출 전에 예산을 예약하고 실패·재개 비용도 남긴다. 저장·권한 오류를 성공으로 폴백하지 않는다.

## 7. 지속 상태·추적

transform_id·seed·원본/변환 hash·변경 필드·independent property report. 정답은 Agent 비노출.

node_id·logical_run_id·session_id·입출력 ref·상태·에러·실행 시간을 run_events에 연결한다. 저장 형식·복구 우선순위는 [지속 상태 계약](../contracts/persistence-and-recovery.md)을 따른다.

## 8. 최소 검증 사례

| 사례 | 확인할 결과 |
|---|---|
| 동일 두 금액 swap | 반례로 세지 않음 |
| 다른 두 금액 swap | 합계 동일·거래별 불일치 2개 |
| 정상 ID 변환 | 검증 통과 |
| 다른 batch 근거 | 대상 binding 실패 |
