# N-08 · propose_action — 조치 제안과 근거 연결

> **설계 초안 v0.1 / 미구현** · P0 · 소속 [B-03](../big-nodes/B-03.md). [Small Node 목록](README.md) · [공통 반환](common-result-contract.md)

## 1. 단일 책임과 실행 경계

한국어 사건 해석과 구조화 증거를 연결하여 조치를 제안한다. 계산·승인·권한 판정은 코드의 결과를 사용한다.

- LLM 사용: **선택한 수행 모델 1회/조사 라운드**.
- 업무 Tool: 직접 Tool 호출 없음. [TOOL-03](../tools/TOOL-03.md)의 실행 전 검사와 구분.
- 이 문서의 내부 함수는 설계 함수다. 별도 Tiny Node나 별도 LLM 호출로 세지 않는다.
- 순서·조건부 엣지는 소속 Big Node가 관리한다. 이 노드는 다음 노드를 직접 실행하지 않는다.

## 2. 입력 계약

| 입력 | 타입·제약·출처 |
|---|---|
| `CaseContext, AsOfEvidence` | 범위·정책과 검증된 사실 |
| `remaining_budget` | 추가 조사 가능한지 확인 |
| `allowed_actions` | WAIT / ESCALATE / REPROCESS / OBSERVE |

하네스는 ID·계약 버전·권한 binding을 검사한 상태를 전달한다. 모델이 작성한 ID나 상태를 검증 없이 신뢰하지 않는다.

## 3. 내부 처리 순서

1. 원본 접수와 코드가 계산한 일치·도착 상태를 구분하여 모델에 제시한다.
2. 행동·이유 코드·근거 ID를 제한된 JSON으로 생성한다.
3. WAIT는 도착 미완료, REPROCESS는 입력 완비·거래별 일치·실패 배치 등 결정적 규칙과 대조한다.
4. 모델이 근거 ID·승인·효과를 지어내면 제안을 거부하거나 부족한 관측으로 돌린다.
5. 확신 점수로 규칙 위반을 통과시키지 않고 최종 실행 허가는 후속 코드에 맡긴다.

## 4. 구현할 내부 함수

| 함수 개념 | 책임 |
|---|---|
| `draft_action(context, evidence)` | 모델 해석·제안 |
| `validate_action_proposal(proposal, facts)` | enum·refs·모의 업무 규칙 |
| `bind_proposal_to_snapshot(proposal)` | 입력·시점·규칙 버전 참조 |

업무 실행 노드는 `node(state: ReconciliationState, services: RuntimeServices) -> NodeResult[T]`를 기본 인터페이스로 한다. 평가 노드 N-16~19는 별도 `EvaluationContext`를 입력받으며 Agent State와 공유하지 않는다.

## 5. 출력 계약

공통 `status/data/diagnostics/outcome` 외피를 유지한다. 아래는 `data`의 최소 결과다.

| 결과 | 내용 |
|---|---|
| `ActionProposal` | action·reason_codes·evidence_refs·미확정 항목 |
| `proposal_validation` | 업무 규칙 적합성·허용 대상·누락 근거 |

| outcome 후보 | 뜻 |
|---|---|
| `wait_proposed` | 당시 도착 미완료 |
| `escalation_proposed` | 불일치·확인 불가 |
| `reprocess_proposed` | 승인 절차를 시작할 수 있는 제안 |
| `observe_proposed` | 예산 내 추가 조회 필요 |

`status=success`는 이 함수의 검사가 정상 종료됐다는 뜻이다. 대사 일치·쓰기 성공·최종 완료·공격 방어 성공은 각 업무 결과와 실제 상태로 판정한다. partial 허용 여부는 안전한 관측 보존에 한정하며 승인·쓰기·완료 허가를 partial로 통과시키지 않는다.

## 6. 오류·재시도·예산

| 오류·조건 | 처리 |
|---|---|
| `MODEL_OUTPUT_INVALID` | 근거 없는 제안을 실행하지 않음 |
| `EVIDENCE_STALE` | 새 근거 구성 필요 |
| `BUDGET_EXHAUSTED` | 추가 모델 호출 없이 실패·이관 근거 보존 |

재시도 여부는 상위 Big Node와 공통 누적 예산이 결정한다. Tool·모델 호출 전에 예산을 예약하고 실패·재개 비용도 남긴다. 저장·권한 오류를 성공으로 폴백하지 않는다.

## 7. 지속 상태·추적

모델·프롬프트 hash, 제안·refs·규칙 검사 결과. 승인 상태는 여기서 생성하지 않는다.

node_id·logical_run_id·session_id·입출력 ref·상태·에러·실행 시간을 run_events에 연결한다. 저장 형식·복구 우선순위는 [지속 상태 계약](../contracts/persistence-and-recovery.md)을 따른다.

## 8. 최소 검증 사례

| 사례 | 확인할 결과 |
|---|---|
| 불완전 입력 | WAIT |
| 금액 교환 | 총액 일치만 보고 REPROCESS 금지 |
| 허위 approval_id 출력 | 승인 레코드로 사용하지 않음 |
| 정상 보안 인용문 | 자료가 유효하면 정상 업무 제안 가능 |
