# N-12 · resolve_uncertain_operation — 미확정 효과·입력 관계 구분

> **설계 초안 v0.1 / 미구현** · P1 · 소속 [B-04](../big-nodes/B-04.md). [Small Node 목록](README.md) · [공통 반환](common-result-contract.md)

## 1. 단일 책임과 실행 경계

관측으로 가능한 상태를 좁히고 결과 회수·재조사·제한 조회·이관 중 필요한 사실을 반환한다.

- LLM 사용: **사용하지 않음**.
- 업무 Tool: [TOOL-05](../tools/TOOL-05.md), 필요 시 [TOOL-01](../tools/TOOL-01.md).
- 이 문서의 내부 함수는 설계 함수다. 별도 Tiny Node나 별도 LLM 호출로 세지 않는다.
- 순서·조건부 엣지는 소속 Big Node가 관리한다. 이 노드는 다음 노드를 직접 실행하지 않는다.

## 2. 입력 계약

| 입력 | 타입·제약·출처 |
|---|---|
| `OperationIntent, possible_states` | 중단 전 ID·키·입력과 최대 4가설 |
| `current CaseContext` | 새 세션의 scope·현재 입력 |
| `recovery budget` | 남은 상태 조회·재시도 횟수 |

하네스는 ID·계약 버전·권한 binding을 검사한 상태를 전달한다. 모델이 작성한 ID나 상태를 검증 없이 신뢰하지 않는다.

## 3. 내부 처리 순서

1. TOOL-05로 operation_id 또는 정규화 업무 키를 조회한다.
2. 입력이 확인되지 않았으면 TOOL-01로 현재 version을 읽는다.
3. 반영 효과와 입력 변경을 독립적으로 갱신한다. evaluator 정답 상태는 읽지 않는다.
4. NOT_FOUND는 authoritative·inflight-free·safe_to_retry_same_key 증명이 있을 때만 미반영으로 분류한다.
5. SUCCEEDED는 결과 회수, 입력 변경은 새 계획, 불명은 상한 내 추가 조회·이관으로 분류한다.

## 4. 구현할 내부 함수

| 함수 개념 | 책임 |
|---|---|
| `observe_operation(intent, ctx)` | 상태·결과 조회 |
| `update_possible_states(states, observation)` | 모순되는 가설만 제거 |
| `classify_recovery_action(observed, budget)` | 효과·입력·권위성에 따른 반환 |

업무 실행 노드는 `node(state: ReconciliationState, services: RuntimeServices) -> NodeResult[T]`를 기본 인터페이스로 한다. 평가 노드 N-16~19는 별도 `EvaluationContext`를 입력받으며 Agent State와 공유하지 않는다.

## 5. 출력 계약

공통 `status/data/diagnostics/outcome` 외피를 유지한다. 아래는 `data`의 최소 결과다.

| 결과 | 내용 |
|---|---|
| `RecoveryObservation` | observed_effect·input_relation·operation_state·canonical ID·result_ref |
| `recovery disposition` | RETRIEVE / REPLAN / RETRY_SAME_INTENT / WAIT_OBSERVATION / ESCALATE |

| outcome 후보 | 뜻 |
|---|---|
| `result_retrieved` | 반영 완료 근거 회수 |
| `retry_candidate` | 미반영·같은 의도 재시도 허용 |
| `replan_required` | 입력 변경 |
| `unresolved` | 확인 불가·추가 조회/이관 필요 |

`status=success`는 이 함수의 검사가 정상 종료됐다는 뜻이다. 대사 일치·쓰기 성공·최종 완료·공격 방어 성공은 각 업무 결과와 실제 상태로 판정한다. partial 허용 여부는 안전한 관측 보존에 한정하며 승인·쓰기·완료 허가를 partial로 통과시키지 않는다.

## 6. 오류·재시도·예산

| 오류·조건 | 처리 |
|---|---|
| `TOOL_TIMEOUT` | UNKNOWN 유지, 예산 내 조회 |
| `OBSERVATION_CONFLICT` | 임의 확정 없이 이관 |
| `BUDGET_EXHAUSTED` | 미확정 사실을 보존해 종료 |
| `SCOPE_DENIED` | 접근 범위 확장 금지 |

재시도 여부는 상위 Big Node와 공통 누적 예산이 결정한다. Tool·모델 호출 전에 예산을 예약하고 실패·재개 비용도 남긴다. 저장·권한 오류를 성공으로 폴백하지 않는다.

## 7. 지속 상태·추적

가능 상태 집합·관측 ref·축별 판정·조회 수·재시도 허가의 근거.

node_id·logical_run_id·session_id·입출력 ref·상태·에러·실행 시간을 run_events에 연결한다. 저장 형식·복구 우선순위는 [지속 상태 계약](../contracts/persistence-and-recovery.md)을 따른다.

## 8. 최소 검증 사례

| 사례 | 확인할 결과 |
|---|---|
| 같은 timeout·반영 전/후 쌍 | 조회 후 구분 |
| APPLIED+CHANGED | 과거 효과 보존·새 조사 |
| 비권위 404 | 미반영 확정 금지 |
| 항상 조회 실패 | 상한 후 근거 있는 이관 |
