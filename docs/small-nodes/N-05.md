# N-05 · collect_evidence — 허용 조회 실행·증거 등록

> **설계 초안 v0.1 / 미구현** · P0 · 소속 [B-02](../big-nodes/B-02.md). [Small Node 목록](README.md) · [공통 반환](common-result-contract.md)

## 1. 단일 책임과 실행 경계

InvestigationPlan을 실행하여 출처·시점·coverage가 있는 EvidenceBundle을 만든다. 빈 결과와 조회 실패를 구분한다.

- LLM 사용: **사용하지 않음**.
- 업무 Tool: [TOOL-02](../tools/TOOL-02.md).
- 이 문서의 내부 함수는 설계 함수다. 별도 Tiny Node나 별도 LLM 호출로 세지 않는다.
- 순서·조건부 엣지는 소속 Big Node가 관리한다. 이 노드는 다음 노드를 직접 실행하지 않는다.

## 2. 입력 계약

| 입력 | 타입·제약·출처 |
|---|---|
| `InvestigationPlan` | 검증된 profile·대상 IDs |
| `TrustedCallContext` | 현재 scope·시각·예산 |
| `expected_input_version` | 읽을 스냅샷 버전 |

하네스는 ID·계약 버전·권한 binding을 검사한 상태를 전달한다. 모델이 작성한 ID나 상태를 검증 없이 신뢰하지 않는다.

## 3. 내부 처리 순서

1. 호출 전 예산을 예약하고 TOOL-02로 각 허용 profile을 실행한다.
2. 응답 envelope의 case/batch/version/as_of와 요청을 대조한다.
3. 전체 비교·페이징의 complete와 summary_complete를 구분한다.
4. 구조화 관측과 외부 메모를 분리해 evidence registry에 등록한다.
5. 일부 조회 실패는 안전한 결과만 partial로 보존한다. 불완전 조회를 부정 증거로 등록하지 않는다.

## 4. 구현할 내부 함수

| 함수 개념 | 책임 |
|---|---|
| `dispatch_query(plan_item, ctx)` | Tool 호출·예산 |
| `validate_query_response(response, request)` | 출처·범위·버전·coverage |
| `register_evidence(validated)` | 불변 ref·predicate/result hash 생성 |

업무 실행 노드는 `node(state: ReconciliationState, services: RuntimeServices) -> NodeResult[T]`를 기본 인터페이스로 한다. 평가 노드 N-16~19는 별도 `EvaluationContext`를 입력받으며 Agent State와 공유하지 않는다.

## 5. 출력 계약

공통 `status/data/diagnostics/outcome` 외피를 유지한다. 아래는 `data`의 최소 결과다.

| 결과 | 내용 |
|---|---|
| `EvidenceBundle` | evidence_id·predicate·facts·row_refs·input_version·as_of·coverage |
| `query_diagnostics` | 완료·실패·truncation·집계 완결성 |

| outcome 후보 | 뜻 |
|---|---|
| `evidence_ready` | 필요 관측 확보 |
| `partial_evidence` | 일부 안전한 관측만 확보 |
| `no_matching_records` | 완전한 지정 조회 0건 |
| `evidence_unavailable` | 유효 관측 없음 |

`status=success`는 이 함수의 검사가 정상 종료됐다는 뜻이다. 대사 일치·쓰기 성공·최종 완료·공격 방어 성공은 각 업무 결과와 실제 상태로 판정한다. partial 허용 여부는 안전한 관측 보존에 한정하며 승인·쓰기·완료 허가를 partial로 통과시키지 않는다.

## 6. 오류·재시도·예산

| 오류·조건 | 처리 |
|---|---|
| `SNAPSHOT_INCOMPLETE` | 쓰기·완료의 전체 근거로 사용 금지 |
| `VERSION_CONFLICT` | 그 버전들을 한 bundle로 섞지 않음 |
| `SCOPE_DENIED` | 넓은 조회로 fallback 금지 |

재시도 여부는 상위 Big Node와 공통 누적 예산이 결정한다. Tool·모델 호출 전에 예산을 예약하고 실패·재개 비용도 남긴다. 저장·권한 오류를 성공으로 폴백하지 않는다.

## 7. 지속 상태·추적

쿼리·결과 집합·빈 결과·coverage·footprint·이벤트 시점과 refs.

node_id·logical_run_id·session_id·입출력 ref·상태·에러·실행 시간을 run_events에 연결한다. 저장 형식·복구 우선순위는 [지속 상태 계약](../contracts/persistence-and-recovery.md)을 따른다.

## 8. 최소 검증 사례

| 사례 | 확인할 결과 |
|---|---|
| 완전한 0건 | success/no_matching_records |
| 조회 실패 뒤 0건 | 0건 증거 아님 |
| 다른 버전 응답 | 반환 거부 |
| 행 반환 일부 제한 | 완결된 서버 집계와 상세 누락을 분리 |
