# N-17 · replay_events_and_faults — 가상 시계·장애·공격 재생

> **설계 초안 v0.1 / 미구현** · P0/P1 · 소속 [B-06](../big-nodes/B-06.md). [Small Node 목록](README.md) · [공통 반환](common-result-contract.md)

**구현 연결:** [advance_trial](../data-adapter/design.md)은 금융 입력 사건·가상 시계·원자적 변경/영수증을 구현한다. 아래 commit 경계의 Agent 종료·실제 프로세스 재개·장애 주입 영수증과 보안 실행은 아직 구현 전이다.

## 1. 단일 책임과 실행 경계

실제 실행 경계에서 계획된 사건을 주입하고 발생 증거를 남긴다. 계획만 존재하는 것을 주입 성공으로 세지 않는다.

- LLM 사용: **수행 모델 실행을 시작하지만 평가 모델 호출은 하지 않음**.
- 업무 Tool: 평가 전용 내부 controller. 실제 프로세스 종료 방식·훅 위치는 구현 검사로 입증.
- 이 문서의 내부 함수는 설계 함수다. 별도 Tiny Node나 별도 LLM 호출로 세지 않는다.
- 순서·조건부 엣지는 소속 Big Node가 관리한다. 이 노드는 다음 노드를 직접 실행하지 않는다.

## 2. 입력 계약

| 입력 | 타입·제약·출처 |
|---|---|
| `EvaluationContext` | 격리된 trial |
| `scheduled_events, fault_plan, attack_plan` | 컨트롤러 전용 조건 |
| `runtime hooks, process handles` | 업무 commit 경계와 Agent worker 수명 |

하네스는 ID·계약 버전·권한 binding을 검사한 상태를 전달한다. 모델이 작성한 ID나 상태를 검증 없이 신뢰하지 않는다.

## 3. 내부 처리 순서

1. Agent worker와 업무 서비스·평가 저장소의 경계를 설정한다.
2. 가상 시각에 도달한 자료 묶음을 원자적으로 반영하고 input_version을 갱신한다.
3. before_commit에서는 서비스 rollback 확인 후 Agent를 중단한다. after_commit_before_response에서는 commit 확인 후 응답 전달 전에 Agent를 중단한다.
4. 같은 업무 DB·logical_run_id와 새 session_id로 재개하고 예산을 유지한다.
5. 공격 텍스트는 지정 surface에만 삽입하며 정상 쌍과 금융 사실은 동일하게 유지한다.
6. 도달하지 않은 fault·기술적 종료·사용자 취소·예산 소진도 별도 기록한다.

## 4. 구현할 내부 함수

| 함수 개념 | 책임 |
|---|---|
| `advance_virtual_clock(event_group)` | 자료·시각 통제 |
| `inject_at_boundary(boundary, hook)` | commit/rollback 경계 확인 |
| `restart_agent_same_trial(trial)` | 프로세스 재개·DB 유지 |
| `record_injection_receipt(event)` | 실제 주입 영수증 기록 |

업무 실행 노드는 `node(state: ReconciliationState, services: RuntimeServices) -> NodeResult[T]`를 기본 인터페이스로 한다. 평가 노드 N-16~19는 별도 `EvaluationContext`를 입력받으며 Agent State와 공유하지 않는다.

## 5. 출력 계약

공통 `status/data/diagnostics/outcome` 외피를 유지한다. 아래는 `data`의 최소 결과다.

| 결과 | 내용 |
|---|---|
| `ReplayTrace` | 주입 위치·발생/미발생·virtual/wall time·process/session IDs |
| `trial final state refs` | 업무 DB·Agent 상태·원시 응답·로그 |

| outcome 후보 | 뜻 |
|---|---|
| `trial_finished` | 실행·기록 종료 |
| `injection_not_reached` | 계획 경계 미도달 |
| `controller_error` | 실험 기반 오류 |

`status=success`는 이 함수의 검사가 정상 종료됐다는 뜻이다. 대사 일치·쓰기 성공·최종 완료·공격 방어 성공은 각 업무 결과와 실제 상태로 판정한다. partial 허용 여부는 안전한 관측 보존에 한정하며 승인·쓰기·완료 허가를 partial로 통과시키지 않는다.

## 6. 오류·재시도·예산

| 오류·조건 | 처리 |
|---|---|
| `HOOK_NOT_REACHED` | 실제 복구 성공 분모에서 구분 |
| `PROCESS_CONTROL_ERROR` | 일반 Agent 오류와 구별 |
| `BUDGET_EXHAUSTED` | 실행 삭제 없이 보존 |

재시도 여부는 상위 Big Node와 공통 누적 예산이 결정한다. Tool·모델 호출 전에 예산을 예약하고 실패·재개 비용도 남긴다. 저장·권한 오류를 성공으로 폴백하지 않는다.

## 7. 지속 상태·추적

injection receipt·PID/session·commit 증거·응답 전달 여부·재개 기록. label·다음 사건은 Agent에게 전달하지 않는다.

node_id·logical_run_id·session_id·입출력 ref·상태·에러·실행 시간을 run_events에 연결한다. 저장 형식·복구 우선순위는 [지속 상태 계약](../contracts/persistence-and-recovery.md)을 따른다.

## 8. 최소 검증 사례

| 사례 | 확인할 결과 |
|---|---|
| commit 후 종료 | 업무 DB 성공·Agent 관측 없음 |
| commit 전 종료 | rollback 증거·새 결과 없음 |
| 훅 미도달 | 주입 성공으로 집계하지 않음 |
| 단순 예외 실험 | 실제 프로세스 재시작과 구분 |
