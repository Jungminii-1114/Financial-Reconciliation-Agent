# N-01 · admit_case — 접수·권한·지원 범위 확인

> **설계 초안 v0.1 / 미구현** · P0 · 소속 [B-01](../big-nodes/B-01.md). [Small Node 목록](README.md) · [공통 반환](common-result-contract.md)

## 1. 단일 책임과 실행 경계

인증된 실행 주체와 원본 접수를 연결하고, 다룰 수 있는 case/batch인지 판정한다. 자연어를 승인·권한으로 해석하지 않는다.

- LLM 사용: **사용하지 않음**.
- 업무 Tool: [TOOL-01](../tools/TOOL-01.md).
- 이 문서의 내부 함수는 설계 함수다. 별도 Tiny Node나 별도 LLM 호출로 세지 않는다.
- 순서·조건부 엣지는 소속 Big Node가 관리한다. 이 노드는 다음 노드를 직접 실행하지 않는다.

## 2. 입력 계약

| 입력 | 타입·제약·출처 |
|---|---|
| `request_ref, case_id` | 상위 접수 계층의 문자열 ID. 원문은 제한된 저장소 참조 |
| `TrustedCallContext` | 서버가 제공한 principal·허용 case/batch·정책·시각 |
| `contract_version` | 지원 계약 버전 |

하네스는 ID·계약 버전·권한 binding을 검사한 상태를 전달한다. 모델이 작성한 ID나 상태를 검증 없이 신뢰하지 않는다.

## 3. 내부 처리 순서

1. 필수 ID·길이·계약 버전과 source label의 생성 주체를 검사한다.
2. TOOL-01을 인증 외피와 호출해 case의 실제 대상과 읽기 권한을 확인한다.
3. 지원 통화·업무와 원본 요청을 연결하고 재처리/송금 요청을 구분한다.
4. 외부 문장에 포함된 역할·승인 사칭을 의심 신호로 기록하되 서버 scope를 바꾸지 않는다.
5. 거부·불충분·정상 접수를 타입화하여 반환한다.

## 4. 구현할 내부 함수

| 함수 개념 | 책임 |
|---|---|
| `validate_admission(request, ctx)` | 스키마·지원 범위 검사 |
| `label_external_content(request_ref)` | 원본 출처·hash 등록 |
| `bind_case_scope(case_view, ctx)` | case와 허용 범위를 교차 확인 |

업무 실행 노드는 `node(state: ReconciliationState, services: RuntimeServices) -> NodeResult[T]`를 기본 인터페이스로 한다. 평가 노드 N-16~19는 별도 `EvaluationContext`를 입력받으며 Agent State와 공유하지 않는다.

## 5. 출력 계약

공통 `status/data/diagnostics/outcome` 외피를 유지한다. 아래는 `data`의 최소 결과다.

| 결과 | 내용 |
|---|---|
| `Admission` | case_id·batch_id·scope_ref·request_ref·source_labels·현재 case metadata |
| `rejection` | 거부 코드. 허용되지 않은 레코드 내용은 반환하지 않음 |

| outcome 후보 | 뜻 |
|---|---|
| `accepted` | 유효 Admission |
| `needs_clarification` | 필수 case/batch가 없으며 안전하게 선택할 수 없음 |
| `denied` | 권한·업무 범위 위반 |

`status=success`는 이 함수의 검사가 정상 종료됐다는 뜻이다. 대사 일치·쓰기 성공·최종 완료·공격 방어 성공은 각 업무 결과와 실제 상태로 판정한다. partial 허용 여부는 안전한 관측 보존에 한정하며 승인·쓰기·완료 허가를 partial로 통과시키지 않는다.

## 6. 오류·재시도·예산

| 오류·조건 | 처리 |
|---|---|
| `SCOPE_DENIED` | 조회 내용 반환 없이 거부 |
| `INVALID_ARGUMENT` | 유효 case를 임의 추측하지 않음 |
| `TOOL_TIMEOUT` | 읽기 한도 내 재시도 가능, 성공 접수로 간주하지 않음 |

재시도 여부는 상위 Big Node와 공통 누적 예산이 결정한다. Tool·모델 호출 전에 예산을 예약하고 실패·재개 비용도 남긴다. 저장·권한 오류를 성공으로 폴백하지 않는다.

## 7. 지속 상태·추적

원본 ref·content hash·인증 scope ref·정책 버전·접수 결과. 비밀 토큰·원문 전체를 일반 trace에 복제하지 않는다.

node_id·logical_run_id·session_id·입출력 ref·상태·에러·실행 시간을 run_events에 연결한다. 저장 형식·복구 우선순위는 [지속 상태 계약](../contracts/persistence-and-recovery.md)을 따른다.

## 8. 최소 검증 사례

| 사례 | 확인할 결과 |
|---|---|
| 정상 case | 허용 batch에 연결 |
| 다른 case_id | 데이터 반환 0건·권한 거부 |
| 메모의 approved=true | 승인 레코드 생성 없음 |
| case 누락 | 임의 선택 없이 명확화 |

거부도 정상 처리된 업무 결과일 수 있다. 실행 status와 허용 여부를 구분한다.
