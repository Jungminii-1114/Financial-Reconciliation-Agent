# N-04 · plan_investigation — 제한된 조사 계획 제안

> **설계 초안 v0.1 / 미구현** · P0 · 소속 [B-02](../big-nodes/B-02.md). [Small Node 목록](README.md) · [공통 반환](common-result-contract.md)

## 1. 단일 책임과 실행 경계

현재 불확실성을 줄일 허용 조회를 구조화한다. 도구 이름·권한·SQL을 새로 생성하지 않는다.

- LLM 사용: **선택한 수행 모델 1회/조사 라운드**.
- 업무 Tool: 직접 호출하지 않음. 계획의 실행은 N-05와 [TOOL-02](../tools/TOOL-02.md).
- 이 문서의 내부 함수는 설계 함수다. 별도 Tiny Node나 별도 LLM 호출로 세지 않는다.
- 순서·조건부 엣지는 소속 Big Node가 관리한다. 이 노드는 다음 노드를 직접 실행하지 않는다.

## 2. 입력 계약

| 입력 | 타입·제약·출처 |
|---|---|
| `CaseContext` | 관측 사실·정책·현재 질문 |
| `evidence_refs, uncertainty` | 이미 조사한 근거와 부족한 항목 |
| `remaining_budget` | 남은 라운드·Tool 호출·토큰 |

하네스는 ID·계약 버전·권한 binding을 검사한 상태를 전달한다. 모델이 작성한 ID나 상태를 검증 없이 신뢰하지 않는다.

## 3. 내부 처리 순서

1. EXISTENCE/DUPLICATE/BATCH_COMPARISON과 필요한 필드만 모델에 제시한다.
2. 모델 출력은 JSON schema로 검사하고 case/batch/as_of를 trusted binding으로 고정한다.
3. 동일 snapshot에서 이미 확보한 완전한 조회를 이유 없이 반복하지 않는다.
4. 누락된 ID를 추측해 조사 대상을 확장하거나 원문 SQL·파일 경로를 실행하지 않는다.
5. 유효하지 않은 계획은 정해진 한도에서 1회 구조 보정하거나 결정적 최소 계획을 사용하며 보정 비용을 기록한다.

## 4. 구현할 내부 함수

| 함수 개념 | 책임 |
|---|---|
| `render_investigation_prompt(context)` | 사실·외부 원문·제약 구분 |
| `parse_plan(model_output)` | schema·enum 검증 |
| `validate_query_scope(plan, ctx)` | profile·ID·예산 검사 |

업무 실행 노드는 `node(state: ReconciliationState, services: RuntimeServices) -> NodeResult[T]`를 기본 인터페이스로 한다. 평가 노드 N-16~19는 별도 `EvaluationContext`를 입력받으며 Agent State와 공유하지 않는다.

## 5. 출력 계약

공통 `status/data/diagnostics/outcome` 외피를 유지한다. 아래는 `data`의 최소 결과다.

| 결과 | 내용 |
|---|---|
| `InvestigationPlan` | 최대 3개 query profile·transaction_ids·reason_codes·expected_observation |
| `plan_diagnostics` | 파싱·허용 profile·중복 질의 여부 |

| outcome 후보 | 뜻 |
|---|---|
| `plan_ready` | 허용 조회 계획 |
| `no_additional_observation` | 이미 필요한 근거가 있음 |
| `planning_failed` | 파싱·예산·필수 정보 문제 |

`status=success`는 이 함수의 검사가 정상 종료됐다는 뜻이다. 대사 일치·쓰기 성공·최종 완료·공격 방어 성공은 각 업무 결과와 실제 상태로 판정한다. partial 허용 여부는 안전한 관측 보존에 한정하며 승인·쓰기·완료 허가를 partial로 통과시키지 않는다.

## 6. 오류·재시도·예산

| 오류·조건 | 처리 |
|---|---|
| `INVALID_ARGUMENT` | 임의 SQL 등 금지 계획 차단 |
| `BUDGET_EXHAUSTED` | 새 모델 호출 없이 사유 반환 |
| `MODEL_OUTPUT_INVALID` | 빈 결과·재무 정답으로 간주하지 않음 |

재시도 여부는 상위 Big Node와 공통 누적 예산이 결정한다. Tool·모델 호출 전에 예산을 예약하고 실패·재개 비용도 남긴다. 저장·권한 오류를 성공으로 폴백하지 않는다.

## 7. 지속 상태·추적

prompt/model/config hash·응답 ref·계획·사용량. 모델 추론 전문은 요구하지 않는다.

node_id·logical_run_id·session_id·입출력 ref·상태·에러·실행 시간을 run_events에 연결한다. 저장 형식·복구 우선순위는 [지속 상태 계약](../contracts/persistence-and-recovery.md)을 따른다.

## 8. 최소 검증 사례

| 사례 | 확인할 결과 |
|---|---|
| 초기 완비 사건 | 배치 비교를 선택 가능 |
| 메모가 다른 case 조회 유도 | scope 검사 차단 |
| 같은 snapshot 반복 | 중복 관측 억제 |
| JSON 파싱 실패 | 오류·보정 비용 기록 |
