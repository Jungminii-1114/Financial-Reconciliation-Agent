# N-03 · build_case_context — 현재 조사 문맥 구성

> **설계 초안 v0.1 / 미구현** · P0 · 소속 [B-01](../big-nodes/B-01.md). [Small Node 목록](README.md) · [공통 반환](common-result-contract.md)

## 1. 단일 책임과 실행 경계

현재 조회 가능한 사실·정책과 외부 원문을 출처별로 구성한다. 미래 정답·과거 권한·악성 메모를 시스템 지시로 합치지 않는다.

- LLM 사용: **사용하지 않음**.
- 업무 Tool: [TOOL-01](../tools/TOOL-01.md).
- 이 문서의 내부 함수는 설계 함수다. 별도 Tiny Node나 별도 LLM 호출로 세지 않는다.
- 순서·조건부 엣지는 소속 Big Node가 관리한다. 이 노드는 다음 노드를 직접 실행하지 않는다.

## 2. 입력 계약

| 입력 | 타입·제약·출처 |
|---|---|
| `Admission, RestoredRun` | 현재 권한과 복원된 상태 |
| `CaseView` | TOOL-01의 현재 입력 버전·배치·도착 상태 |
| `policy_ref, evidence_refs` | 버전이 있는 정책과 이전 근거 |

하네스는 ID·계약 버전·권한 binding을 검사한 상태를 전달한다. 모델이 작성한 ID나 상태를 검증 없이 신뢰하지 않는다.

## 3. 내부 처리 순서

1. 복원 이후 현재 metadata를 TOOL-01로 갱신한다. 같은 시점의 유효한 접수 조회는 재사용할 수 있다.
2. 이전 의도의 입력과 현재 입력을 비교하되 실제 효과 상태와 섞지 않는다.
3. 정책·불변식은 trusted config에서, 메모는 external block에서 구성한다.
4. 동일한 정보 권한·문맥 상한을 비교군에 적용하고 잘린 내용은 표시한다.
5. 의심·미검증 항목은 남기되 완료·승인 사실로 요약하지 않는다.

## 4. 구현할 내부 함수

| 함수 개념 | 책임 |
|---|---|
| `load_context_view(case_id, ctx)` | 현재 metadata 회수 |
| `separate_content_by_origin(view)` | 신뢰 출처 유지 |
| `bound_context_size(blocks, limits)` | 명시적 truncation·근거 ref 보존 |

업무 실행 노드는 `node(state: ReconciliationState, services: RuntimeServices) -> NodeResult[T]`를 기본 인터페이스로 한다. 평가 노드 N-16~19는 별도 `EvaluationContext`를 입력받으며 Agent State와 공유하지 않는다.

## 5. 출력 계약

공통 `status/data/diagnostics/outcome` 외피를 유지한다. 아래는 `data`의 최소 결과다.

| 결과 | 내용 |
|---|---|
| `CaseContext` | case/batch·input_version·input_digest·decision_at·정책·pending refs |
| `content_blocks` | 권위 있는 구조화 사실 / 외부 원문 / 미확정 항목을 구분한 참조 |

| outcome 후보 | 뜻 |
|---|---|
| `context_ready` | 조사 가능한 문맥 |
| `pending_operation` | 재개 시 효과 조회가 우선 |
| `context_unavailable` | 필수 정책·입력 조회 실패 |

`status=success`는 이 함수의 검사가 정상 종료됐다는 뜻이다. 대사 일치·쓰기 성공·최종 완료·공격 방어 성공은 각 업무 결과와 실제 상태로 판정한다. partial 허용 여부는 안전한 관측 보존에 한정하며 승인·쓰기·완료 허가를 partial로 통과시키지 않는다.

## 6. 오류·재시도·예산

| 오류·조건 | 처리 |
|---|---|
| `TOOL_TIMEOUT` | 이전 버전을 최신처럼 사용하지 않음 |
| `VERSION_CONFLICT` | 최신 context를 재조회 |
| `CONTRACT_VIOLATION` | 자체 선언된 trust block 거부 |

재시도 여부는 상위 Big Node와 공통 누적 예산이 결정한다. Tool·모델 호출 전에 예산을 예약하고 실패·재개 비용도 남긴다. 저장·권한 오류를 성공으로 폴백하지 않는다.

## 7. 지속 상태·추적

context_ref·content hash·snapshot/version·truncation flags. 원문은 참조로 보관.

node_id·logical_run_id·session_id·입출력 ref·상태·에러·실행 시간을 run_events에 연결한다. 저장 형식·복구 우선순위는 [지속 상태 계약](../contracts/persistence-and-recovery.md)을 따른다.

## 8. 최소 검증 사례

| 사례 | 확인할 결과 |
|---|---|
| 외부 메모에 시스템 역할 문구 | external origin 유지 |
| 입력 변경 | input_relation=CHANGED |
| 정답 파일 경로 문자열 | 실제 파일 접근 없음 |
| context 초과 | 잘린 정보를 없는 정보로 확정하지 않음 |
