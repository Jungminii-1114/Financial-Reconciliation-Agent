# N-16 · load_evaluation_case — 평가 사례·정답·실행 격리 준비

> **설계 초안 v0.1 / 미구현** · P0 · 소속 [B-06](../big-nodes/B-06.md). [Small Node 목록](README.md) · [공통 반환](common-result-contract.md)

**구현 연결:** [trial 적재/재개 API](../data-adapter/README.md)는 구현됐다. 초기 fixture·역할별 저장소·identity·READY를 준비한다. N-16의 평가 실행 인덱스·모델/config 동결·Agent 시작 연결 전체를 구현한 것은 아니다.

## 1. 단일 책임과 실행 경계

평가 전용 권한으로 초기 DB·미래 사건·정답을 읽고, Agent에는 현재 관측만 전달한다.

- LLM 사용: **사용하지 않음**.
- 업무 Tool: 모델 Tool 없음. 평가 fixture·DB 어댑터.
- 이 문서의 내부 함수는 설계 함수다. 별도 Tiny Node나 별도 LLM 호출로 세지 않는다.
- 순서·조건부 엣지는 소속 Big Node가 관리한다. 이 노드는 다음 노드를 직접 실행하지 않는다.

## 2. 입력 계약

| 입력 | 타입·제약·출처 |
|---|---|
| `scenario_id, split, seed, scenario_version` | 동결된 사례 식별자 |
| `initial fixture, event/fault/attack plan, expected spec` | 분리된 평가 입력 |
| `setting/model/config/repeat_id` | 비교 설정과 반복 ID |

하네스는 ID·계약 버전·권한 binding을 검사한 상태를 전달한다. 모델이 작성한 ID나 상태를 검증 없이 신뢰하지 않는다.

## 3. 내부 처리 순서

1. manifest hash·계약·스키마와 개발/평가 split 계열을 검사한다.
2. trial마다 업무·Agent 상태 DB를 새로 만들고 같은 trial의 재개에는 파일을 유지한다.
3. 교육용 case_002 이벤트 묶음·버전과 내부 known_at 적재 가정을 명시한다.
4. controller_only/evaluator_only는 Agent Tool의 경로·repository에서 제외한다.
5. baseline/H에 같은 초기 업무 데이터·허용 정보·승인 시뮬레이터를 제공한다.

## 4. 구현할 내부 함수

| 함수 개념 | 책임 |
|---|---|
| `validate_scenario_manifest(spec)` | hash·버전·split 검사 |
| `materialize_trial(spec, setting)` | 격리 DB 생성 |
| `create_observable_admission(trial)` | 정답·미래 미노출 |

업무 실행 노드는 `node(state: ReconciliationState, services: RuntimeServices) -> NodeResult[T]`를 기본 인터페이스로 한다. 평가 노드 N-16~19는 별도 `EvaluationContext`를 입력받으며 Agent State와 공유하지 않는다.

## 5. 출력 계약

공통 `status/data/diagnostics/outcome` 외피를 유지한다. 아래는 `data`의 최소 결과다.

| 결과 | 내용 |
|---|---|
| `EvaluationContext` | trial_id·격리 DB 경로·case refs·정답 hash·허용 서비스 |
| `initial Agent admission` | 관측 가능한 case와 인증된 테스트 scope만 |

| outcome 후보 | 뜻 |
|---|---|
| `case_loaded` | 재현 가능한 실행 준비 |
| `case_rejected` | 정답·fixture·분리 무결성 문제 |

`status=success`는 이 함수의 검사가 정상 종료됐다는 뜻이다. 대사 일치·쓰기 성공·최종 완료·공격 방어 성공은 각 업무 결과와 실제 상태로 판정한다. partial 허용 여부는 안전한 관측 보존에 한정하며 승인·쓰기·완료 허가를 partial로 통과시키지 않는다.

## 6. 오류·재시도·예산

| 오류·조건 | 처리 |
|---|---|
| `DATASET_INVALID` | Agent 성능 실패와 구분 |
| `SPLIT_LEAKAGE` | 최종 평가 동결 보류 |
| `ISOLATION_ERROR` | 공유 DB 실행 중단 |

재시도 여부는 상위 Big Node와 공통 누적 예산이 결정한다. Tool·모델 호출 전에 예산을 예약하고 실패·재개 비용도 남긴다. 저장·권한 오류를 성공으로 폴백하지 않는다.

## 7. 지속 상태·추적

trial index·초기 DB hash·scenario/config/model hash. 정답은 evaluator 권한에만 보관.

node_id·logical_run_id·session_id·입출력 ref·상태·에러·실행 시간을 run_events에 연결한다. 저장 형식·복구 우선순위는 [지속 상태 계약](../contracts/persistence-and-recovery.md)을 따른다.
