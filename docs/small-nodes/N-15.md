# N-15 · deliver_result — 확정 결과·근거·한계 전달

> **설계 초안 v0.1 / 미구현** · P0 · 소속 [B-05](../big-nodes/B-05.md). [Small Node 목록](README.md) · [공통 반환](common-result-contract.md)

## 1. 단일 책임과 실행 경계

FinalDecision 또는 실행 전 종료 사유를 사용자에게 전달한다. 새 조사·승인·사실 판단을 추가하지 않는다.

- LLM 사용: **기본은 결정적 템플릿, 추가 LLM 서식화는 P2**.
- 업무 Tool: 필요 시 [TOOL-06](../tools/TOOL-06.md).
- 이 문서의 내부 함수는 설계 함수다. 별도 Tiny Node나 별도 LLM 호출로 세지 않는다.
- 순서·조건부 엣지는 소속 Big Node가 관리한다. 이 노드는 다음 노드를 직접 실행하지 않는다.

## 2. 입력 계약

| 입력 | 타입·제약·출처 |
|---|---|
| `FinalDecision 또는 admission/execution rejection` | 확정 결과나 전달 가능한 종료 사유 |
| `safe evidence refs, report_facts` | 검증된 사실·미확정 항목 |
| `output policy` | 표시할 case 정보·금지 필드·언어 |

하네스는 ID·계약 버전·권한 binding을 검사한 상태를 전달한다. 모델이 작성한 ID나 상태를 검증 없이 신뢰하지 않는다.

## 3. 내부 처리 순서

1. 확정된 사실·판정 상태와 미확정 내용을 분리한다.
2. ESCALATED이면 TOOL-06으로 evidence refs를 검사한 이관 초안을 만든다.
3. 결정적 한국어 템플릿으로 결과·시점·확인 범위와 후속 행동을 구성한다.
4. 출력 정책의 금지 필드·민감정보 형식·HTML 표현을 검사한다. 비밀 canary 값에 대한 노출 판정은 evaluator N-19가 수행한다.
5. 사용자 전달 실패는 업무 재실행으로 해결하지 않고 같은 decision ref로 재전달한다.

## 4. 구현할 내부 함수

| 함수 개념 | 책임 |
|---|---|
| `build_report_facts(decision)` | 확정 facts와 한계 |
| `render_user_report(facts)` | 결정적 템플릿 |
| `validate_output_policy(report)` | 금지 노출·근거 ref 검사 |

업무 실행 노드는 `node(state: ReconciliationState, services: RuntimeServices) -> NodeResult[T]`를 기본 인터페이스로 한다. 평가 노드 N-16~19는 별도 `EvaluationContext`를 입력받으며 Agent State와 공유하지 않는다.

## 5. 출력 계약

공통 `status/data/diagnostics/outcome` 외피를 유지한다. 아래는 `data`의 최소 결과다.

| 결과 | 내용 |
|---|---|
| `UserReport` | 조치·근거·시점/버전·작업/결과 ref·한계·후속 확인 |
| `escalation draft` | 이관 필요 시 구조화된 보고 초안, 실제 발송 없음 |

| outcome 후보 | 뜻 |
|---|---|
| `delivered` | 전달 가능한 결과 |
| `escalation_draft_ready` | 보고 초안 생성 |
| `delivery_blocked` | 출력 정책·전달 실패 |

`status=success`는 이 함수의 검사가 정상 종료됐다는 뜻이다. 대사 일치·쓰기 성공·최종 완료·공격 방어 성공은 각 업무 결과와 실제 상태로 판정한다. partial 허용 여부는 안전한 관측 보존에 한정하며 승인·쓰기·완료 허가를 partial로 통과시키지 않는다.

## 6. 오류·재시도·예산

| 오류·조건 | 처리 |
|---|---|
| `PROHIBITED_OUTPUT` | 민감 출력 제거·필요 시 전달 차단 |
| `UNKNOWN_EVIDENCE_REF` | 허위 인용 거부 |
| `DELIVERY_FAILED` | 같은 결정으로 재전달, 새 쓰기 금지 |

재시도 여부는 상위 Big Node와 공통 누적 예산이 결정한다. Tool·모델 호출 전에 예산을 예약하고 실패·재개 비용도 남긴다. 저장·권한 오류를 성공으로 폴백하지 않는다.

## 7. 지속 상태·추적

final_report_ref·decision_id·전달 상태·노출 검사. 일반 로그에 금지 원문을 복제하지 않는다.

node_id·logical_run_id·session_id·입출력 ref·상태·에러·실행 시간을 run_events에 연결한다. 저장 형식·복구 우선순위는 [지속 상태 계약](../contracts/persistence-and-recovery.md)을 따른다.

## 8. 최소 검증 사례

| 사례 | 확인할 결과 |
|---|---|
| 확인 불가 | 성공 문장 생성 없음 |
| 이관 | 실제 메일·메시지 발송 없음 |
| 출력 실패 뒤 재개 | 같은 decision 사용 |
| 응답 내 금지 필드 | runtime 출력 정책으로 차단, canary 노출은 evaluator가 독립 판정 |
