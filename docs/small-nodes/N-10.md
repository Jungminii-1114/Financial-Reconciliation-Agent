# N-10 · persist_operation_intent — 실행 직전 검사·의도 영속화

> **설계 초안 v0.1 / 미구현** · P0 · 소속 [B-03](../big-nodes/B-03.md). [Small Node 목록](README.md) · [공통 반환](common-result-contract.md)

## 1. 단일 책임과 실행 경계

쓰기 전에 승인된 계획의 작업 ID·업무 키·입력 binding을 durable하게 남긴다. 마지막 권한·버전 검사는 업무 Tool이 다시 수행한다.

- LLM 사용: **사용하지 않음**.
- 업무 Tool: 모델 업무 Tool 없음. [지속 상태·예산 서비스](../tools/internal-services.md).
- 이 문서의 내부 함수는 설계 함수다. 별도 Tiny Node나 별도 LLM 호출로 세지 않는다.
- 순서·조건부 엣지는 소속 Big Node가 관리한다. 이 노드는 다음 노드를 직접 실행하지 않는다.

## 2. 입력 계약

| 입력 | 타입·제약·출처 |
|---|---|
| `ApprovalPlan` | 현재 APPROVED 계획 |
| `existing_pending_intent` | 같은 계획의 미확정 의도 또는 null |
| `remaining_budget, TrustedCallContext` | 현재 권한·시각·남은 실행 횟수 |

하네스는 ID·계약 버전·권한 binding을 검사한 상태를 전달한다. 모델이 작성한 ID나 상태를 검증 없이 신뢰하지 않는다.

## 3. 내부 처리 순서

1. 계획·승인·현재 scope·만료와 입력 참조를 확인한다.
2. 같은 논리 계획에 pending 의도가 있으면 ID와 키를 유지한다. 효과가 불명확한 의도를 새 키로 교체하지 않는다.
3. 새 계획은 코드로 operation_id와 정규화된 idempotency_key를 생성한다.
4. 의도·순번·예산 예약을 Agent 저장소에 commit하고 성공을 확인한다.
5. 그 뒤에만 READY를 반환한다. 이 검사와 실제 commit 사이 경쟁은 TOOL-04가 처리한다.

## 4. 구현할 내부 함수

| 함수 개념 | 책임 |
|---|---|
| `derive_business_key(plan)` | 정규화된 멱등 키 |
| `persist_intent(intent)` | 쓰기 이전 durable 저장 |
| `reserve_dispatch_budget(intent)` | 재개에도 유지되는 시도 예약 |

업무 실행 노드는 `node(state: ReconciliationState, services: RuntimeServices) -> NodeResult[T]`를 기본 인터페이스로 한다. 평가 노드 N-16~19는 별도 `EvaluationContext`를 입력받으며 Agent State와 공유하지 않는다.

## 5. 출력 계약

공통 `status/data/diagnostics/outcome` 외피를 유지한다. 아래는 `data`의 최소 결과다.

| 결과 | 내용 |
|---|---|
| `OperationIntent` | operation_id·idempotency_key·case/batch·input_version·action_digest·approval_id |
| `dispatch_state` | READY / BLOCKED |

| outcome 후보 | 뜻 |
|---|---|
| `intent_ready` | 지속 저장 완료, 발행 가능 |
| `intent_reused` | 기존 동일 의도 유지 |
| `intent_blocked` | 승인·권한·예산·저장 문제 |

`status=success`는 이 함수의 검사가 정상 종료됐다는 뜻이다. 대사 일치·쓰기 성공·최종 완료·공격 방어 성공은 각 업무 결과와 실제 상태로 판정한다. partial 허용 여부는 안전한 관측 보존에 한정하며 승인·쓰기·완료 허가를 partial로 통과시키지 않는다.

## 6. 오류·재시도·예산

| 오류·조건 | 처리 |
|---|---|
| `APPROVAL_STALE` | 발행 전 중단 |
| `IDEMPOTENCY_CONFLICT` | 키의 의미 변경 거부 |
| `STORAGE_ERROR` | Tool 발행 0회 |
| `BUDGET_EXHAUSTED` | 새 실행 금지·기존 pending 보존 |

재시도 여부는 상위 Big Node와 공통 누적 예산이 결정한다. Tool·모델 호출 전에 예산을 예약하고 실패·재개 비용도 남긴다. 저장·권한 오류를 성공으로 폴백하지 않는다.

## 7. 지속 상태·추적

operation_intents가 복구의 정본. framework checkpoint가 늦어도 이 journal을 먼저 확인한다.

node_id·logical_run_id·session_id·입출력 ref·상태·에러·실행 시간을 run_events에 연결한다. 저장 형식·복구 우선순위는 [지속 상태 계약](../contracts/persistence-and-recovery.md)을 따른다.

## 8. 최소 검증 사례

| 사례 | 확인할 결과 |
|---|---|
| 의도 commit 후 Agent 종료 | 재개가 같은 ID 조회 |
| 저장 실패 | 업무 Tool 호출 없음 |
| 재시도 | 같은 키 유지 |
| 승인 뒤 입력 변경 | 후속 Tool도 stale 쓰기 차단 |
