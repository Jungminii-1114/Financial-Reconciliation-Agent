# N-11 · execute_operation — 승인된 재처리 발행·응답 관측

> **설계 초안 v0.1 / 미구현** · P0 · 소속 [B-04](../big-nodes/B-04.md). [Small Node 목록](README.md) · [공통 반환](common-result-contract.md)

## 1. 단일 책임과 실행 경계

저장된 의도를 TOOL-04에 발행하고 검증된 응답을 관측으로 남긴다. 응답 유실은 미반영으로 바꾸지 않는다.

- LLM 사용: **사용하지 않음**.
- 업무 Tool: [TOOL-04](../tools/TOOL-04.md).
- 이 문서의 내부 함수는 설계 함수다. 별도 Tiny Node나 별도 LLM 호출로 세지 않는다.
- 순서·조건부 엣지는 소속 Big Node가 관리한다. 이 노드는 다음 노드를 직접 실행하지 않는다.

## 2. 입력 계약

| 입력 | 타입·제약·출처 |
|---|---|
| `OperationIntent` | READY인 durable 의도 |
| `TrustedCallContext` | 현재 호출 권한과 Tool 시도 ID |
| `pending budget reservation` | 발행 전에 예약된 사용량 |

하네스는 ID·계약 버전·권한 binding을 검사한 상태를 전달한다. 모델이 작성한 ID나 상태를 검증 없이 신뢰하지 않는다.

## 3. 내부 처리 순서

1. 저장된 의도 ref와 Tool payload가 같은지 확인한다.
2. TOOL-04를 같은 operation/key로 한 번 발행한다.
3. 정상 응답의 canonical operation_id·action binding·result_ref를 검사한다.
4. 기존 같은 키의 결과면 새 효과와 구별하여 회수 사실을 기록한다.
5. 타임아웃·종료·응답 유실이면 pending을 유지하고 효과를 UNKNOWN으로 둔다. 확인 없이 재발행하지 않는다.

## 4. 구현할 내부 함수

| 함수 개념 | 책임 |
|---|---|
| `dispatch_reprocess(intent, ctx)` | 업무 Tool 발행 |
| `validate_operation_response(response, intent)` | canonical ID·범위·버전 확인 |
| `record_dispatch_observation(result)` | 확인 상태와 미확정 상태 저장 |

업무 실행 노드는 `node(state: ReconciliationState, services: RuntimeServices) -> NodeResult[T]`를 기본 인터페이스로 한다. 평가 노드 N-16~19는 별도 `EvaluationContext`를 입력받으며 Agent State와 공유하지 않는다.

## 5. 출력 계약

공통 `status/data/diagnostics/outcome` 외피를 유지한다. 아래는 `data`의 최소 결과다.

| 결과 | 내용 |
|---|---|
| `ExecutionObservation` | 검증된 operation 상태·결과 ref·입력 버전 |
| `pending intent update` | RESPONSE_OBSERVED / EFFECT_UNKNOWN / REJECTED |

| outcome 후보 | 뜻 |
|---|---|
| `applied_observed` | 검증할 결과 확보 |
| `effect_unknown` | 실제 상태 조회 필요 |
| `execution_rejected` | 승인·버전·권한 거부 |
| `execution_failed` | 권위 있게 실패 확인 |

`status=success`는 이 함수의 검사가 정상 종료됐다는 뜻이다. 대사 일치·쓰기 성공·최종 완료·공격 방어 성공은 각 업무 결과와 실제 상태로 판정한다. partial 허용 여부는 안전한 관측 보존에 한정하며 승인·쓰기·완료 허가를 partial로 통과시키지 않는다.

## 6. 오류·재시도·예산

| 오류·조건 | 처리 |
|---|---|
| `TOOL_RESPONSE_LOST` | N-12에서 실제 상태 조회 |
| `VERSION_CONFLICT` | 새 조사·계획, 기존 승인 사용 금지 |
| `CONTRACT_VIOLATION` | 성공 응답이라도 완료 근거로 거부 |

재시도 여부는 상위 Big Node와 공통 누적 예산이 결정한다. Tool·모델 호출 전에 예산을 예약하고 실패·재개 비용도 남긴다. 저장·권한 오류를 성공으로 폴백하지 않는다.

## 7. 지속 상태·추적

dispatch 시도·응답 ref·효과 지식·canonical ID·사용량. 잃어버린 usage는 unknown으로 보존.

node_id·logical_run_id·session_id·입출력 ref·상태·에러·실행 시간을 run_events에 연결한다. 저장 형식·복구 우선순위는 [지속 상태 계약](../contracts/persistence-and-recovery.md)을 따른다.

## 8. 최소 검증 사례

| 사례 | 확인할 결과 |
|---|---|
| commit 후 응답 유실 | UNKNOWN·pending 유지 |
| 동일 키 재요청 | 기존 결과·새 효과 0 |
| 다른 대상 성공 응답 | 계약 위반 |
| 서버 버전 거부 | 완료·쓰기 성공으로 기록하지 않음 |
