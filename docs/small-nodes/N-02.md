# N-02 · restore_run — 체크포인트·미확정 의도 복원

> **설계 초안 v0.1 / 미구현** · P0 · 소속 [B-01](../big-nodes/B-01.md). [Small Node 목록](README.md) · [공통 반환](common-result-contract.md)

## 1. 단일 책임과 실행 경계

같은 logical_run_id의 지속 상태와 쓰기 의도를 복원한다. 체크포인트만 보고 완료·미반영을 확정하지 않는다.

- LLM 사용: **사용하지 않음**.
- 업무 Tool: 없음. [내부 지속 상태 서비스](../tools/internal-services.md) 사용.
- 이 문서의 내부 함수는 설계 함수다. 별도 Tiny Node나 별도 LLM 호출로 세지 않는다.
- 순서·조건부 엣지는 소속 Big Node가 관리한다. 이 노드는 다음 노드를 직접 실행하지 않는다.

## 2. 입력 계약

| 입력 | 타입·제약·출처 |
|---|---|
| `Admission` | N-01이 확인한 현재 scope |
| `logical_run_id, session_id` | 논리 실행은 유지, 새 프로세스의 session은 갱신 |
| `checkpoint_ref, intent_journal` | 하네스 저장소의 durable 기록 |

하네스는 ID·계약 버전·권한 binding을 검사한 상태를 전달한다. 모델이 작성한 ID나 상태를 검증 없이 신뢰하지 않는다.

## 3. 내부 처리 순서

1. 현재 권한과 이전 case/batch/config binding을 교차 확인한다.
2. 체크포인트와 별도 operation_intents를 읽고 누락·순번 차이를 확인한다.
3. 새 session_id를 붙이되 operation_id·업무 키·비용 누계는 유지한다.
4. 이전 evidence와 승인 상태는 재확인 대상으로 표시하며 현재 유효성을 자동 승인하지 않는다.
5. 이전 durable decision_id가 있으면 추가 쓰기 없이 재전달할 참조를 반환한다.

## 4. 구현할 내부 함수

| 함수 개념 | 책임 |
|---|---|
| `load_run_records(logical_run_id)` | 상태·의도·예산 읽기 |
| `validate_restore_binding(records, admission)` | case·config·계약 일치 |
| `merge_recovery_metadata(records)` | 체크포인트보다 앞선 의도 journal 보존 |

업무 실행 노드는 `node(state: ReconciliationState, services: RuntimeServices) -> NodeResult[T]`를 기본 인터페이스로 한다. 평가 노드 N-16~19는 별도 `EvaluationContext`를 입력받으며 Agent State와 공유하지 않는다.

## 5. 출력 계약

공통 `status/data/diagnostics/outcome` 외피를 유지한다. 아래는 `data`의 최소 결과다.

| 결과 | 내용 |
|---|---|
| `RestoredRun` | 상태·미확정 operation·evidence refs·누적 예산·이전 결정 |
| `restore_mode` | fresh / resume_pending / resume_finalized / incompatible |

| outcome 후보 | 뜻 |
|---|---|
| `fresh` | 이전 상태 없음 |
| `pending_operation` | 실제 작업 조회 필요 |
| `finalized` | 과거 결정 회수 가능 |
| `restore_blocked` | 계약·scope·저장 무결성 문제 |

`status=success`는 이 함수의 검사가 정상 종료됐다는 뜻이다. 대사 일치·쓰기 성공·최종 완료·공격 방어 성공은 각 업무 결과와 실제 상태로 판정한다. partial 허용 여부는 안전한 관측 보존에 한정하며 승인·쓰기·완료 허가를 partial로 통과시키지 않는다.

## 6. 오류·재시도·예산

| 오류·조건 | 처리 |
|---|---|
| `STORAGE_ERROR` | 저장 실패를 fresh 실행으로 숨기지 않음 |
| `CONTRACT_VIOLATION` | 호환 불가 상태를 새 쓰기로 우회하지 않음 |
| `SCOPE_DENIED` | 과거 권한을 그대로 재사용하지 않음 |

재시도 여부는 상위 Big Node와 공통 누적 예산이 결정한다. Tool·모델 호출 전에 예산을 예약하고 실패·재개 비용도 남긴다. 저장·권한 오류를 성공으로 폴백하지 않는다.

## 7. 지속 상태·추적

새 session 시작 이벤트·복원 checkpoint seq·pending intent ref·usage 미확정 상태.

node_id·logical_run_id·session_id·입출력 ref·상태·에러·실행 시간을 run_events에 연결한다. 저장 형식·복구 우선순위는 [지속 상태 계약](../contracts/persistence-and-recovery.md)을 따른다.

## 8. 최소 검증 사례

| 사례 | 확인할 결과 |
|---|---|
| commit 후 응답 누락 | pending intent 유지 |
| 재개 | 예산 초기화 없음 |
| 완료 기록 후 출력 누락 | 기존 decision 재전달 |
| 저장소 손상 | fresh fallback 및 쓰기 금지 |
