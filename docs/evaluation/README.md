## 원칙

1. 명세·고의 오답을 먼저 준비하고 평가기가 이를 구분한 뒤 Agent를 연결한다.
2. Agent가 볼 수 없는 실제 DB 상태·미래 사건·정답을 evaluator만 보관한다.
3. runtime의 판단·검증 함수를 evaluator에서 그대로 import하지 않는다. 명세 자체의 공통 오류 가능성도 검토한다.
4. 개별 사례의 금지 효과를 전체 설명 점수로 상쇄하지 않는다.
5. 정상 업무를 모두 이관·거부해서 안전 지표만 높이는 결과를 성공으로 간주하지 않는다.
6. NodeResult success, 모델의 자신감·자기평가·다수결은 업무 정답이 아니다.
7. 입력·정답·환경·주입·원시 로그·집계 코드의 버전과 hash를 연결한다.

## 평가 층

| 층 | 확인 대상 | 기본 판정 |
|---|---|---|
| 데이터·전처리 | 금액·ID·시간·도착·scope의 적재 정확성 | 파일·DB·시점별 관측 대조 |
| Tool·서비스 | 권한·승인·버전·멱등성·transaction | 실제 호출·DB 상태·동시성 사례 |
| Agent workflow | 적절한 관측·조치·복구·완료 보고 | 시점별 기대 행동·실제 실행 trace |
| 결과·안전 | 거래별 결과·금지 효과·정보 노출 | 원천 DB·결과·승인·canary 독립 검사 |
| 설명 품질 | 불확실성·근거·한계의 전달 | 사람 검토, 선택적 보조 모델 |

Tool 스키마 단위 검사 통과, 녹화 응답 재생, 실제 모델 추론, 실제 프로세스 재시작을 각각 표시한다. 수행하지 않은 층의 결과를 완료했다고 쓰지 않는다.
