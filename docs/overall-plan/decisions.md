# 설계 결정·미결정 기록

> 상태: 제안 결정 v0.1. 사용자와 구현자가 검토·파일럿 후 갱신한다. 설계 결정을 구현 완료나 실험 결과로 해석하지 않는다.

| ID | 결정 | 이유·검증 경계 |
|---|---|---|
| D-01 | B-01~05는 생명주기, B-06은 평가 경로 | 단일 대사 업무를 다루므로 ReportAnchor의 목적별 라우팅을 그대로 복제하지 않음 |
| D-02 | 19 Small Node, 6 업무 Tool, 내부 서비스 별도 | 노드=LLM 호출=Tool이라는 혼동 방지. 체크포인트·예산은 횡단 서비스 |
| D-03 | 공통 반환 4필드와 별도의 업무·효과 상태 | `success`를 업무 성공·DB 반영·탐지 성공으로 오해하지 않도록 함 |
| D-04 | 동기·직렬화 업무 서비스부터 시작 | 권위 있는 미반영 확인 조건을 통제. 임의 분산 인플라이트는 UNKNOWN으로 처리 |
| D-05 | 승인 발급은 외부 주체 | Agent의 자연어·위조 승인 필드를 권한으로 사용하지 않음 |
| D-06 | 승인·버전·멱등성 보호는 모든 비교군 공통 | 보호 제거로 H에 유리한 실험을 만들지 않음 |
| D-07 | 효과 상태와 입력 변경은 별도 축 | 반영된 과거 작업을 입력 변경 때문에 미반영으로 오판하지 않음 |
| D-08 | 증거 재사용과 승인 재사용 분리 | 영향 없는 근거는 유지해도 새 입력 버전의 쓰기는 새 승인 필요 |
| D-09 | 판정 당시 정보와 최종 결과를 분리 | 늦게 도착한 정답을 과거 Agent 입력에 섞지 않음 |
| D-10 | runtime 검증기와 evaluator 구현·입력 분리 | 같은 버그가 자동 정답이 되는 것을 줄임. 명세 검토도 별도 필요 |
| D-11 | N-15는 결정적 템플릿 기본 | 새로운 미검증 사실 생성·추가 Tool 호출 방지 |
| D-12 | 모델 교차 검토·Jev는 선택 보조 | DB·금액·시간·승인을 모델 투표로 판정하지 않음 |
| D-13 | finalization은 as-of 결정 기록 | 완료 직전의 조건을 업무 서비스 트랜잭션에서 검사. 이후 입력 변경은 새 검토 사건 |
| D-14 | 실행 도중 정책·계약 변경은 자동 이행하지 않음 | 현재 권한은 재검사하지만, 미확정 의도의 정책·action binding을 새 키로 바꿔 우회하지 않음. 호환 불가면 이관 |
