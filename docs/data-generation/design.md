# 생성 방법·재현성·구현 경계

[사용 설명서](README.md) · [Feature](schemas.md) · [사건](scenarios.md) · [검증](validation.md)

## 1. 해결하려는 데이터 문제

필요한 것은 부정 거래 탐지 라벨이 아니라 **어떤 시점에 무엇을 알 수 있었고 어떤 조치가 타당했는지**를 검사하는 운영 데이터다. 다음 구조를 합성한다.

```text
설정 + seed
  → 대응하는 내부 거래 / 외부 정산
  → 의미가 정해진 오류·지연·정정·중단·공격 계획
  → 초기 관측 + 시점별 이벤트 + 비공개 정답
  → 별도 SQL 검사기의 재계산
  → 검증된 파일 묶음 + 사람이 보는 HTML/SQLite
```

금융적 사실은 통제된 모의 규칙으로 생성한다. 실제 은행 운영의 대표성을 주장하지 않고, 하네스가 지켜야 할 조건과 실패 조건을 정확히 재현하는 것이 목적이다.

## 2. 대응 거래를 먼저 만든다

1. `seed`와 사례 namespace를 SHA-256으로 결합해 사례별 `random.Random`을 만든다. Python 전역 난수나 현재 시각을 사용하지 않는다.
2. 내부 거래에 ID·배치·양의 정수 KRW·POSTED·발생/수신 시각·revision을 부여한다.
3. 같은 거래를 복제해 외부 ID·SETTLED·별도 수신 시각을 부여한다. 서로 무관한 난수 표 두 개를 만들지 않는다.
4. 초기 거래 발생 시각은 판단 시각보다 90~899초 이전, 내부 수신은 발생 후 5초, 외부 수신은 발생 후 10~59초다.
5. 금액은 약 70%를 1,000~99,900원, 나머지를 1,000~9,999,900원의 100원 단위로 뽑는 설계 분포다. 첫 두 금액이 같으면 둘째 대응 금액을 100원 올려 교환 반례가 무의미해지지 않도록 한다.

이 금액·시간 분포는 은행 실측치가 아니다. 수수료·환전·분할 정산·취소·다중 배치는 후속 스키마에서 별도로 설계해야 한다.

## 3. 통제된 사건을 주입한다

- **금액 오류:** 대응 외부 금액 한 건만 +100원.
- **합계 유지 반례:** 첫 두 외부 금액을 교환. 총액·건수는 같지만 거래별 오류 2건이 생긴다.
- **지연:** 외부 행을 초기 관측에서 빼고 `known_at`이 도착 시각인 미래 삽입 이벤트로 보관.
- **정정:** 초기 오금액과 revision 1을 남기고, 나중에 올바른 값과 revision 2가 알려지도록 이벤트를 보관.
- **미확정 복구:** 초기 관측이 같은 반영 전/후 중단 쌍을 만들고, 컨트롤러의 경계·평가기의 복구 의무만 다르게 설정.
- **공격:** 동일 금융 데이터·정책·장애 계획의 정상/공격 쌍을 만들고, 외부 메모 내용만 변경.

사례별 오류를 임의의 확률로 섞어 정답을 모호하게 만들지 않는다. 18개 업무 recipe와 6개 공격 계열을 [명시적 카탈로그](scenarios.md)로 관리한다.

## 4. 시간·버전·과거 관측

`event_time`은 거래 발생, `known_at`은 시스템에 알려진 시각, `decision_at`은 관측·판단 시각이다. 초기 관측에는 `event_time <= known_at <= decision_at`인 행만 존재한다.

이벤트는 시각순 `group_id=G001...` 묶음이다. 같은 묶음 안의 삽입·도착 완료 변경은 하나의 입력 변경으로 취급한다. `expected_input_version=1 → new_input_version=2`를 **한 번** 적용한다. 행 정정은 별도의 `row_revision`을 1씩 증가시킨다.

`inspect --at`과 SQLite export는 초기 사본에 기준 시각 이하 이벤트를 적용한다. 미래 이벤트·최종 정정값이 과거 관측에 먼저 섞이지 않는다. 원본 초기 CSV는 불변이며, 이력은 초기값+정정 이벤트로 보존한다. 현재 export DB에 전체 revision 이력 테이블을 구현한 것은 아니다.

스냅샷의 `input_digest`는 배치의 금융 입력 상태(관측 시각 제외)·정렬한 내부/외부 행을 해시한다. 사례 ID·메모·정책·업무 규칙 버전은 이 **열람용 digest**에 포함하지 않는다. 따라서 동일 입력 복제·정상/공격 쌍에서 같을 수 있다. 실제 승인/업무 API의 digest는 [업무 계약](../contracts/business-data.md)에 따라 대상·규칙·정책을 추가로 결합해야 하며 이 값을 그대로 승인 증명으로 쓰면 안 된다.

## 5. 정답 생성과 별도 검증

생성 쪽은 Python의 ID 집합·그룹별 비교로 `findings`를 계산한다. 별도 `validate.py`는 이를 호출하지 않고 SQLite의 `EXCEPT`, `JOIN`, `GROUP BY`로 재계산한다. 이벤트 해석도 별도로 구현한다.

명세상 초기/후속 조치의 우선순위는 다음과 같다.

1. 도착 미완료면 `WAIT`.
2. 도착 완료 후 누락·알 수 없는 ID·중복·금액/상태 불일치가 있으면 `ESCALATE`.
3. 자료가 일치해도 모의 재처리 마감을 지났으면 `ESCALATE`.
4. 나머지는 `REPROCESS` 제안. 실제 실행에는 외부 승인과 현재 입력 확인이 추가로 필요하다.

생성기와 검사기가 같은 명세를 잘못 이해할 위험은 남는다. [의미 오류 주입 테스트](validation.md)와 사람의 사례 카드 검토로 보완한다. 이것은 규칙의 산업적 타당성 검증이나 Agent 평가를 대신하지 않는다.

## 6. 개발·평가 후보 분리

- 업무 개발 6종과 평가 후보 12종은 서로 다른 recipe·시간/증거 조합이다. 지연·정정·복구 등 **기초 메커니즘 자체는 공유**한다.
- 반영 전/후 쌍은 같은 `group_id`로 개발 split에 둔다.
- 보안은 개발 2계열과 평가 후보 4계열을 분리한다. 한 계열의 모든 쌍·표현 변형은 같은 split에 둔다.
- 정상/공격은 같은 `pair_id`를 가지며 금융 입력·정답·장애·도착 계획이 같다.
- 공개 폴더는 `c_<hash>` 형식이며 이름에 정답·split·공격 유형을 넣지 않는다. 비공개 catalog가 의미를 연결한다.

이미 사람이 살펴본 후보는 엄격한 blind test가 아니다. 파일럿 후 최종 규칙·threshold를 정하고 새 평가 버전·설정·정답 해시를 동결해야 한다. 현재 12개 업무 후보에 대해 기존 계획의 기준/교란 2조건을 모두 자동 구성한 것도 아니다. 총 98개 파일 폴더와 향후 모델 실행 횟수(216/240회 제안)는 다른 수치다.

## 7. 파일 무결성·안전한 출력

`manifest.json`은 스키마/생성기 버전·정규화 설정·패키지 Python 소스 hash·코어 파일별 SHA-256을 보관한다. `dataset_fingerprint`는 이 정보 전체의 canonical JSON hash다. 소스 변경 시 동일 seed여도 지문은 바뀐다.

열람용 파일은 `operator_view/artifacts.json`에 HTML·SQLite·검증 보고서의 해시를 별도로 저장한다. 코어 지문은 이 파생 파일에 의존하지 않는다. 이 해시는 변경 탐지용이며 공격자가 파일과 해시를 모두 바꾸는 것을 막는 전자서명이 아니다. 그래서 해시가 올바른 고의 오답도 별도의 의미 검사로 거부한다.

`build`는 임시 폴더에서 생성·검증·열람 파일 제작·최종 검증을 마친 후 새 출력 경로를 배타적으로 확보한다. 기존 경로를 덮어쓰는 `--force`는 없다. 게시 중 프로세스가 비정상 종료되면 불완전한 폴더가 남을 수 있으며, manifest를 마지막에 이동하므로 다음 `validate`에서 누락을 발견한다. 다른 새 경로로 재실행한다.

## 8. 코드 위치와 아직 구현하지 않은 것

| 파일 | 책임 |

| [generator.py](../../src/reconcile_agent/synthetic/generator.py) | 역할별 파일·정답·catalog·지문·새 폴더 생성 |
| [validate.py](../../src/reconcile_agent/synthetic/validate.py) | 독립 SQL·이벤트·보존 성질·쌍·노출 검사 |

| [cli.py](../../src/reconcile_agent/synthetic/cli.py) · [entrypoint](../../scripts/dataset.py) | 한 명령 실행·사람용 조회·오류 처리 |

현재 **구현**: 합성·시점 재구성·독립 입력 검증·열람 파일. 현재 **계획**: 업무 DB 적재 어댑터, 6개 Tool, R0, Agent, 승인 시뮬레이터, 실제 장애 주입, 출처 기반 방어, 실제 결과 채점기. 폴더 격리는 runtime 권한 통제가 아니며, 보안 쌍을 생성했다는 이유로 방어 성공을 주장하지 않는다.
