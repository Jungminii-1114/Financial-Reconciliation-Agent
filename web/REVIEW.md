# UI 검토와 보완 기록 — 2026-11-13

## 판단

사건·Agent 실행·업무 결과를 구분한 7개 화면과 정보 구조는 활용 가능하다. 실행 환경을 추가하고, 모의 화면이 실제 업무 시스템처럼 보이는 표현과 작동하지 않던 인터랙션을 보완했다.

## 주요 수정

- SQLite Online·Live 표기를 연결되지 않은 UI 프로토타입으로 변경하고 화면 전체에 상태 표시.
- 임의의 복구 96.5%·보안 100%·Agent 성능 수치를 제거. 실제 검증 보고서의 111/28 결과와 CLI 관측으로 대체.
- 여섯 Tool의 이름과 효과를 저장소 계약에 일치시킴. TOOL-01은 Python 구현, 나머지는 계획 상태로 표기.
- 수수료 조정·원천 금액 변경 문구를 결과 재생성/대기/이관으로 수정. 예시 금액은 KRW로 표시.
- Overview 건수·그래프를 동일한 5개 예시 사례에서 계산.
- 검색·상태 필터·검색 결과 없음 표시를 실제 목록에 연결.
- 사건 전환 시 Agent/Recovery/승인 상태 초기화. 타이머 정리와 중복 실행 방지.
- Approver의 모의 승인 조건을 실제 버튼과 확인 함수 양쪽에서 검사. 승인 모달의 접근성 이름·키보드 focus·Escape 지원.
- 복구 UI의 Start → Inject → Resume 순서를 검사. 사례·설정 변경 시 초기화.
- 모바일 메뉴·가로 스크롤 표·헤더 줄바꿈 지원.

## 확인한 범위

- `npm run build` 성공.
- 로컬 개발 화면과 프로덕션 preview를 실제 Chromium으로 검토.
- 프로덕션 브라우저의 24개 관측/검사를 통과. 결과 목록은 [review-results.json](review-results.json)에 보관.
- 1440×1000 데스크톱과 390×844 모바일 화면 확인. 7개 화면 이동, 검색·필터·빈 결과, 승인 역할·모달·Escape, 복구 순서·사건 전환, 문서 가로 overflow를 검사.
- 검사 중 pageerror 0건. 테스트 결과는 자동 접근성 인증이나 모든 viewport·브라우저 호환성 보증이 아니다.
- `src/data` 사본을 기존 공개 보고서 JSON과 바이트 단위로 대조.

브라우저 검사 스크립트는 검토 환경의 Playwright로 실행했다. `review-results.json`은 이번 실행의 관측 목록이며 별도의 웹 회귀 테스트 프레임워크를 구현한 것은 아니다. Python 111개를 이번 웹 검사에서 재실행했다는 의미도 아니다.

## 후속 연결

현재는 프론트엔드만 실행된다. Python Tool을 붙일 때에는 별도 서버가 신뢰 문맥·권한·정책·예산을 구성하고, 브라우저의 역할 선택 값을 인증 근거로 사용하지 않아야 한다. 현재 UI 버튼의 상태 전환을 실제 승인 레코드나 DB 반영 증거로 재사용하지 않는다.
