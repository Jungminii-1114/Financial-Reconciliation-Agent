# 운영 워크벤치 화면 명세

`web/src/LiveApp.tsx`와 `web/src/live.css`의 상태 표현 기준이다. 서버 계약(`/api/workspace`, `/api/cases/{id}`, `POST …/actions`)과 SQLite 저장 방식은 바꾸지 않았다. 화면의 모든 값은 서버가 돌려준 관측(`case`)에서 계산한다.

## 화면 구성

데스크톱은 세 패널로 나눈다(사례 탐색 · 검토 보고서 · Agent 검토). 1080px 이하에서는 사례 칩 → Agent 검토(주 버튼 포함) → 보고서 순으로 쌓는다.

1. **사례 탐색(왼쪽)**: P0 `after_commit`을 먼저 두고, 비교 경로 4개를 그 아래에 둔다. 항목마다 현재 단계 점과 문구를 표시한다.
2. **검토 보고서(가운데)**: 문서 바(`{case_id}_대사검토` · 판정 상태) 아래에 다음 내용을 차례로 둔다.
   - 파란 제목 “대사 검토 요약”과 업무 시각·입력 버전
   - KPI 4개: 일치 거래, 검토 필요 예외, 내부 거래 총액, 합계 차이
   - **처리 상태**: 6단계 흐름, 4개 렌즈(실행 · 업무 효과 · 최종 결정 · 독립 검증), 중단 진단, 복구 요약, 버전 안내
   - **거래 대조 결과**: 상태 점이 있는 표
   - **예외 상세**: 불일치·미도착 행마다 카드를 두고, 이관 초안이나 대기 결정과 연결한다.
   - **판정 · 독립 검증**
   - **세션별 도구 호출 원장**
3. **Agent 검토(오른쪽)**: 다음 내용을 차례로 둔다.
   - 조사 요청(사례 정의)
   - 하네스 관측 요약: 주요 발견, 다음 단계, 주 버튼과 새 실험, 직전 조작 결과
   - 근거 출처 5개(내부 거래, 외부 정산, 승인 기록, 호출 원장, 독립 검증): 각각 확인됨·주의·해당 없음·결과 없음 아이콘을 붙인다.
   - 결과 참조(결정 · 작업 · 결과 · 이관 초안)

   주요 발견 문장은 모델이 쓰지 않는다. 화면이 저장된 관측(`summary`, `operations`, `approvals`, `audit`, `evaluation`)에서 만든다.

## 매핑

### `stage` → 현재 단계 / 실행 상태 렌즈

| `stage` | pill | 톤 | 실행 상태 문구 |
| --- | --- | --- | --- |
| `NEW` | 실행 전 | neutral | 조사 세션이 아직 없습니다. |
| `READY` | 조사 준비 | neutral | 조사 세션을 실행할 수 있습니다. |
| `PAUSED_FOR_APPROVAL` | 승인 대기 | info | 조사 세션이 조치를 제안한 뒤 멈췄습니다. 쓰기 호출은 없습니다. |
| `APPROVED` | 실행 대기 | info | 승인이 기록됐고 실행 세션은 아직 시작되지 않았습니다. |
| `INTERRUPTED` | 실행 중단 | warn | 직후 응답에 `exit_code`가 있으면 exit 코드를 표시합니다. 새로고침 뒤에는 원장의 `RESERVED` 호출을 근거로 표시합니다. |
| `FINAL` | 판정 기록 완료 · {outcome} | ok | 현재 입력에 대한 최종 결정을 저장했습니다. |

`FINAL`은 항상 “판정 기록 완료”로 표시한다. “재처리 완료”는 `decision.outcome = REPROCESSED`일 때만 쓰며, `WAITING_FOR_INPUT`(자료 도착 대기)과 `ESCALATED`(담당자 이관)도 같은 초록 톤의 정상 결론으로 표시한다.

### `available` → 버튼

`available` 목록에 있는 조작만 버튼으로 만든다. 사례 실행 기록(trial)이 있으면 `start`가 아닌 첫 조작이 주 버튼이 되고, `start`는 보조 버튼 **새 실험**으로 둔다. 새 실험은 이전 기록을 보존한다.

| 조작 | 버튼 | 스타일 | 다음 조작 설명 |
| --- | --- | --- | --- |
| `start` | 사례 조사 시작 / 새 실험 | primary / ghost | 합성 사건을 별도 업무 DB에 적재하고 조사 세션 실행 |
| `run` | 재처리 실행 | primary (navy) | READY면 조사, APPROVED면 사전 확인 후 재처리 |
| `approve` | 재처리 승인 → 모달 | approve (blue) | 승인 레코드만 생성하고 업무 쓰기는 하지 않음 |
| `interrupt` | 실행 중 프로세스 종료 | fault (red outline) | 커밋 직후 exit 72 / 커밋 직전 exit 71 |
| `resume` | 새 세션에서 복구 | recover (teal) | `get_operation`으로 먼저 확인 |
| `advance` | 지연 자료 반영 및 재조사 | primary | 업무 시각 +5분, 입력 v2로 새 실행 |

요청이 진행 중이면 모든 조작과 사례 전환을 잠그고 info 배너를 띄운다. 오류가 나면 같은 쓰기를 다시 보내지 않고 GET으로 최신 관측을 다시 읽는다. `STATE_CHANGED`, `RUN_BUSY`, `WORKER_TIMEOUT` 배너에는 **다시 읽기** 버튼이 있다.

### 승인 모달

네이티브 `<dialog>`의 `showModal()`을 사용한다. 열리면 **취소**에 포커스를 두고, Tab으로 **승인 기록**으로 이동한다. Escape를 누르거나 취소를 누르면 닫힌다. 모달에는 대상 `case_id · batch_id`, 입력 버전과 digest, 업무 시각, 제안 조치, 기록자, 승인 후 다음 조작을 표시한다. 승인 클릭(요청)과 승인 레코드 관측은 구분한다. 응답이 오면 “직전 조작” 줄에 `approvals[-1].approval_id`와 상태를 표시한다.

### 업무 효과 렌즈

- 값: `operations.length`건. 보조 줄에는 `result_count`행, 현재 버전 승인 상태(`APPROVED` → 기록됨, `CONSUMED` → 사용됨), 결과 참조, `processing_state`를 둔다.
- `INTERRUPTED`이고 작업이 1건 이상이면 info 톤으로 “실행은 중단됐지만 DB에는 재처리 작업이 커밋돼 있습니다.”를 표시한다.
- `INTERRUPTED`이고 작업이 0건이면 “커밋 전에 중단돼 DB에 남은 작업이 없습니다.”를 표시한다.

### `evaluation` → 독립 검증 렌즈

| 값 | 표시 |
| --- | --- |
| `null` | **결과 없음** (neutral) · 패널 태그 “미실행” |
| `passed: true` | **통과** (ok) · N개 검사, 기대 = 관측 outcome |
| `passed: false` | **실패** (danger) · 실패한 검사 수, 기대 / 관측 outcome |

### 호출 원장

`audit[]`를 `session_id` 기준으로 처음 나온 순서대로 묶는다. 세션 역할은 다음 순서로 정한다. 첫 호출이 `get_operation`이면 복구 세션, `RESERVED`가 있으면 중단된 실행 세션, `execute_reprocess`가 있으면 실행 세션, `prepare_escalation`이 있으면 이관 세션이고, 나머지는 조사 세션이다. 쓰기 도구는 `execute_reprocess`와 `prepare_escalation`이다. 예산 막대는 `budget.used / max_attempts`이고, 세션별 구간으로 나누어 표시한다.

## 사례별 강조

- **after_commit**: 중단 배너에 “실행은 중단됐고, 업무 효과는 DB에 반영돼 있습니다.”를 표시한다. 복구 뒤 요약에는 세션 2의 쓰기 시도 1회(RESERVED)와 세션 3의 읽기 2회·쓰기 0회를 비교하고, 결과 참조 옆에 “DB 작업과 동일” 태그를 붙인다.
- **before_commit**: 중단 직후 작업 0건이고 업무 반영 단계는 “미반영”이다. 복구 요약은 “확인 후 실행 · 쓰기 1회”이며 최종 작업은 1건이다.
- **delayed_arrival**: v1에서는 미도착 행을 `—`로 표시하고 “v1 결정: 자료 도착 대기” 안내를 붙인다. v2에서는 v1의 저장 결정·승인·작업·호출 건수를 표시한다. v1 결정 상세는 별도 이력 조회 계약이 생긴 뒤 추가한다.
- **amount_swap**: 합계 차이 0과 거래별 1/3 일치를 나란히 둔다. 어긋난 행은 amber 배경과 왼쪽 막대로 표시하고, 표 아래에 로컬 이관 초안 `draft_id`를 연결한다.
- **clean**: 승인과 실행이 서로 다른 버튼과 단계로 나뉘는 기준 경로다.

## 표기 규칙

- 금액은 정수 KRW로 표시하고 `ko-KR` 천 단위 구분, 우측 정렬, tabular 숫자를 쓴다. 빈 값은 `—`이다.
- 시각은 `YYYY-MM-DD HH:mm KST`로 표시한다.
- 긴 ID와 digest는 `앞 10자…뒤 6자`로 줄인다. 누르면 전체 값이 펼쳐지고, `title`에도 전체 값을 둔다.
- 상태는 항상 색과 텍스트를 함께 쓴다(ok/warn/danger/info/neutral).
- 뷰포트는 1440px 데스크톱과 390px 모바일을 확인했다. 1080px 이하에서는 한 열로 쌓고, 넓은 표는 표 영역 안에서만 가로 스크롤한다.
